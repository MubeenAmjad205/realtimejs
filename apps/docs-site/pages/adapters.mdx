# Adapters

RealtimeJS uses an **Adapter-Driven Architecture**. This means the core engine contains the business logic, offline queueing, and state management, but it delegates the actual network operations to adapters.

## Official Adapters

### @realtimejs/adapter-socketio

The official Socket.IO transport layer. It bridges the gap between Socket.IO's bidirectional event architecture and RealtimeJS's standard adapter contract.

```typescript
import { createSocketIOAdapter } from '@realtimejs/adapter-socketio';

const transport = createSocketIOAdapter('https://your-socket-server.com');
```

### @realtimejs/adapter-websocket

The official native WebSocket transport layer. It utilizes the browser's native `WebSocket` API, requiring absolutely no third-party dependencies. Perfect for Edge environments.

```typescript
import { createWebSocketAdapter } from '@realtimejs/adapter-websocket';

const transport = createWebSocketAdapter('wss://your-websocket-server.com/ws');
```

### @realtimejs/adapter-postgres

The official PostgreSQL adapter. It operates as a blazing-fast schemaless document store using a single `JSONB` column, allowing it to seamlessly handle highly dynamic realtime objects (like reactions or editing history) without requiring constant schema migrations.

```typescript
import { createPostgresAdapter } from '@realtimejs/adapter-postgres';

const database = createPostgresAdapter('postgres://user:pass@localhost:5432/realtime');
```

### @realtimejs/adapter-s3

The official AWS S3 storage adapter. Safely upload media using `PutObjectCommand` and automatically resolve public edge-cached URLs.

```typescript
import { createS3Adapter } from '@realtimejs/adapter-s3';

const storage = createS3Adapter('my-realtime-bucket', 'us-east-1');
```

## Creating Custom Adapters

You can build your own custom adapter for databases, storage, or transport. To ensure your custom adapter complies with the RealtimeJS standard, run it against our built-in Contract Test Suite!

```typescript
import { runTransportAdapterContractTests } from '@realtimejs/core/src/adapters/ContractTestSuite';
```

Ran command: `npm version minor --workspaces`

The error you're encountering is a classic monorepo publishing gotcha!

When you run `npm version`, NPM successfully updates all the `package.json` files to `0.2.0`, but then it automatically attempts to run an `npm install` to update your `package-lock.json`. During that install, it checks the public NPM registry for `@realtimejs/events@^0.1.1` to resolve dependencies, but since it has **never been published before**, the registry returns a 404 Not Found, causing the command to crash.

Additionally, as noted in the README, you cannot publish packages under the `@realtimejs` namespace unless you explicitly own that organization on NPM.

Here is the exact strategy to successfully publish:

### Option 1: Rename to Your Own NPM Scope (Recommended)

If you don't own the `@realtimejs` organization on NPM, you will get a `403 Forbidden` error when you try to publish anyway. You need to do a global find-and-replace in your codebase to change `@realtimejs/` to your personal NPM username (e.g., `@mubeen/`):

1. Replace all instances of `"@realtimejs/` with `"@yourusername/` across all `package.json` files.
2. Run `npm install` to relink the local workspaces.
3. Commit the changes, then run `npm publish --workspaces --access public`.

### Option 2: Skip the Install Step (If you own the `@realtimejs` org)

If you _do_ own the organization and just want to get past this 404 error so you can publish for the very first time, tell NPM to skip the automatic install step during versioning:

```bash
npm version minor --workspaces --no-git-tag-version --ignore-scripts
```

_(Note: You might need to revert the previous partial `npm version` changes using `git reset --hard` before running this)._

Then, publish them to the registry:

```bash
npm publish --workspaces --access public
```
